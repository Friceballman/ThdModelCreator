# 設計案 ver3.0｜資料整備・全体像確認・Blender対話編集

状態：対話検証用のCLI、Blender比較レンダー、編集セッションの接続・保存照合を実装済み。画像生成サービスによる資料画像の自動作成と、稼働中のBlender MCPサーバーへの接続試験は未実施。

本書は3D制作ハーネス ver2.0を動作試験で得た知見に基づいて更新する案である。ver2.0の実装基準は引き続き [仕様書 ver2.0](spec-v2.0.md) とし、本案への合意・実装を経ずに既存動作を変更しない。

## 1. 背景と対象課題

案件62cf5801-d02a-41ff-8c06-dac99e5b38eaでは、15部品の画像資料を作り、Blenderで部品造形・組立てを13回反復した。ポーズ・配色・大きな構成は確認できたが、服の皺、胴と腕の接合、手・靴・ホルスターの輪郭に大きな差が残った。造形スクリプトはプリミティブや手作成メッシュを組み合わせており、参照画像から立体輪郭を直接復元する方式ではなかった。各部品の補助画像は1枚ずつで、上面や厳密な背面形状を十分に拘束できなかった。

本案では、資料の方向不足、低ポリ形状の解釈ずれ、全身での部品間不整合、Blender上の修正指示と保存候補の断絶、完成版が曖昧なまま作業が終わる問題を扱う。

## 2. ver3.0の制作フロー案

1. 元資料を不変の参照として登録し、部品ごとに由来・優先度・保持条件を固定する。
2. 低ポリ部品を想定した資料パックを作る。部品形状、寸法比、取付位置、確定事項と推定を分ける。
3. 正面・側面・上面の三面図を必須でそろえる。背面図は資料がある場合に追加し、補完生成した場合は推定資料として区別する。
4. 部品資料と元資料を参照して、部品を組み合わせた完成予想図を画像として作る。これは造形開始前に全体の比率・配置・配色を確認するための資料で、3Dモデルや実測図として扱わない。
5. 利用者が資料パックと完成予想図を確認する。修正が必要なら資料工程へ戻り、確認済み内容とhashを固定する。
6. Blenderで低ポリの全身候補を造形し、正面・側面・上面を最低限確認する。背面・斜め方向も必要に応じて確認する。
7. 利用者が編集対象の候補IDを指定する。CodexはそのIDに対応するモデルをBlender MCPで開き、利用者と同じモデル状態を見ながら調整する。
8. 調整ごとに元候補を保持したまま派生候補を記録し、同じ参照視点で差分を確認する。
9. 作業終了時には完成版を候補IDで1つ指定する。IDが指定されるまでは制作を完了扱いにしない。正式採用・source出力は別の判断として保つ。

## 3. 資料パック契約案

各対象部品の資料パックには次を含める。

- 元資料のID、hash、参照領域、優先順位
- 部品別の低ポリ造形ガイド画像または構築図
- 正面・側面・上面の方向別資料
- 可能な場合の背面資料。生成・推定した場合は `method=image_generation`、`inferred=true` と根拠・不確実性を記録
- 寸法比、座標系、接続アンカー、隣接部品との重なり
- 部品形状の特徴、維持する輪郭、低ポリ化で省略する細部
- 部品資料と元資料との一致確認、および未解決の矛盾
- 部品案を組み合わせ、元資料を参照して作る全身完成予想図と生成条件

三面図が揃わない場合は、画像生成で補完するか、ユーザーに追加資料を求める。生成・補完した方向は実測資料と同じ扱いにしない。資料パックに必須視点がない、またはユーザー確認が済んでいない間は、造形工程へ進めない。

完成予想図は「画像上の構成確認用」と「Blenderの実モデルから出すプレビュー」を別種の成果物として登録する。画像だけで部品の接合・厚み・背面形状が確定したとは扱わない。

## 4. Blender MCPによる候補ID指定編集案

編集開始時に、利用者は案件内の候補IDを指定する。ハーネスは候補IDから `.blend` の案件相対パス、hash、親候補、部品IDを解決し、Blender MCPが接続しているシーンの対象ファイルと照合する。不一致や接続先不明時は編集を開始しない。

編集は登録済み候補への上書きではなく、候補から作業コピーを作る。CodexはMCPを介してその共有シーンを参照・操作し、指示対象の部品ID、操作、変更理由、前後の画像、保存結果をrunへ記録する。保存・再読込・hash検証後に新しい派生候補IDを発行する。未登録のBlender画面や別案件のモデルを対象候補として推測しない。

候補IDを基準にすることで、ユーザーが見ているモデルとCodexが修正するモデルを一致させる。MCP接続状態、Blenderプロセス、対象ファイルのhash、作業コピーの保存先をセッション開始時と候補化時に記録する。

## 5. 完成版IDと状態遷移案

各制作単位は `completion_candidate_id` を高々1件持つ。完成候補を確定する作業では、終了時にこのIDを必ず1つ設定する。候補ID未設定の状態は `in_progress` または `blocked` とし、完了として報告・出力しない。修正を続ける場合はIDの差し替え履歴を残す。

`completion_candidate_id` は、その作業で完成版として指定した候補を示す。候補の `selected`、案件の正式採用 `approved_candidate_id`、source出力とは区別する。外観の不一致が残る場合、理由と未達項目を記録し、候補を完成版として誤表示しない。

回数上限や外部要因で反復を続けられない場合も、未完成候補を自動で完成版にしない。利用者が明示的に作業を保留・中止した場合は未完了状態と理由を残す。

## 6. 品質確認・受け入れ条件案

- 造形開始前に、全対象部品の正面・側面・上面資料、由来、推定事項、完成予想図が固定され、利用者確認を記録できる。
- 完成予想図とBlender実モデルのプレビューを別種として識別できる。
- 候補IDから正しい案件・`.blend`・hashを解決し、MCP接続中のシーンと一致しない場合は停止する。
- MCP編集は親候補を保持して新しいrun・候補IDに保存され、操作と変更対象を追跡できる。
- 部品の接合、厚み、輪郭を複数方向で確認し、機械的構造検査と見た目のレビューを別々に記録する。
- 元資料との比較は要件単位で `pass / fail / uncertain / not_applicable` と理由・方向・画像IDを記録する。画像を確認できない項目は合格扱いにしない。
- 作業完了時に完成版候補IDがちょうど1つ指定されている。未指定なら状態は未完了である。
- Blender保存成功、メッシュ検査合格、候補登録成功を外観品質の合格へ読み替えない。
- 反復の評価では、完成度に加え、差分の縮小、修正所要時間、変更対象以外の保持、接合不良、処理時間・メモリを記録する。

## 7. 既存仕様との関係と変更範囲

案件・参照・候補・runのID追跡、元資料と候補の不変性、Blenderを唯一の3D実行先とすること、ユーザーレビューと正式採用の分離、静止形状とUE・動作検証の分離はver2.0から維持する。

追加する中心要件は、必須三面図と任意背面、低ポリ部品ガイド、造形前の全身完成予想図、候補IDからのBlender MCP編集セッション、完成版候補IDの必須記録である。MCPは既存Blender操作の追跡・対話方法を追加するもので、別の3D実行先を追加しない。

v3を新規案件から選択でき、v2案件の自動移行はしない。Blender MCP経由で `scripts/blender_session.py` の `connect` と `capture` を呼ぶと、接続中シーンの候補ID・作業コピー・hash・部品IDを記録する。ハーネスは `candidate edit-bind` と `edit-finish` でその記録を照合する。ライブMCPサーバー接続は環境側の起動後に別途検証する。

## 9. 全体像と部品をつなぐ反復レビュー案

造形前に作る完成予想図は、全体構成を人が確認する補助資料として有効だが、それだけでは反復修正の閉ループにならない。画像生成で補った誤りが全体目標へ混入する可能性があり、全体の差異をどの部品または接合へ戻すかも記録されないためである。一次資料は引き続き優先し、完成予想図は利用者確認済みの二次目標として扱う。

各反復を次の手順で行う。

1. **比較条件を固定する。** 元資料の参照領域、候補ID、カメラ方向、投影、画角、全身スケール、照明を記録する。比較画像は同じ条件で作り、位置合わせ後の差を観察できるようにする。
2. **全体像を点検する。** 正面・側面・上面を基本に、背面・斜めも必要な場合は追加する。ポーズ、全高に対する各部の比率、外形、重なり、全身の色配置を確認する。
3. **差異を問題票にする。** 問題ごとに `issue_id`、要件ID、証拠となる参照ID・画像領域、方向、差異の説明、優先度、確実性、状態を記録する。問題種別は `part_shape / part_transform / interface / material / reference_gap` などから選ぶ。
4. **問題を修正対象へ割り当てる。** `affected_part_ids` と必要なら部品間の接続IDを指定し、形状、配置、接合、材質、資料不足のどこを直すかを記録する。全体形状の問題を部品へ無理に押し付けず、複数部品の関係なら関係修正として扱う。資料不足や矛盾は造形修正で隠さず、資料工程へ戻す。
5. **優先問題を選んで派生候補を作る。** 高優先度の問題を中心に、修正対象を限定した新しい部品候補または組立候補を作る。親候補、対象部品、変更意図、維持条件を固定し、元候補は保持する。
6. **部品と全体の両方で再確認する。** 修正部品の単体画像と、組み立てた全身画像を同じ視点で比較する。対象問題が `resolved / reduced / unchanged / regressed / unclear` のどれかを記録し、関連する他部品・全身の退行も確認する。
7. **未解決問題を次の反復へ渡す。** 未解決・退行した問題を閉じず、次の修正計画へ引き継ぐ。対象問題が縮小し、必須保持条件に退行がない場合に限り、その候補を次の基準候補として使う。
8. **完了条件を確認する。** 案件の必須見た目要件に未解決の `fail` がなく、不確実点が解決または利用者判断済みになった候補から、完成版IDを1つ指定する。基準を満たす候補がない場合は反復中または未完了とし、候補を便宜上完成扱いにしない。

この記録により、全体像の指摘が部品候補の修正へ伝わり、その修正が全身で改善したかを確認できる。品質を単一の自動点数へ圧縮せず、全体と各部品の差異、保持違反、未確定事項を別々に追う。反復の進行は、優先度別の未解決問題数、修正後の状態、差分画像、修正所要時間で判断する。

### 別途生成する全体像資料の役割

- **完成予想図**：部品資料と元資料から画像生成し、造形前の全体比率・配置・色を利用者が確認するために使う。参照元と推定部分を記録し、元資料より低い優先度にする。
- **反復比較シート**：生成画像ではなく、元資料の該当領域とBlenderから同条件で出した実モデル画像を並べる、または重ねる。差異を発見し、問題票の証拠として使う。
- **Blender全身プレビュー**：現在の実モデルから作る。完成予想図の代わりにしない。問題票を部品ID・接続IDへ割り当てる根拠として使う。

したがって、別途生成する全体像画像は全体構成の初期ずれを減らす助けにはなるが、差異を修正対象へ配る機能の代替にはならない。問題票、部品・接続への割当、修正後の二段階確認を加えて初めて、全体比較が各部品の修正まで届く。
## 実装済みの範囲と利用方法

- 新規案件は `mwb project create --workflow-version 3 ...` でv3として開始できる。既定はv2で、既存案件の自動移行は行わない。
- v3の資料パックは、部品ごとの `images[].view` に `front` / `side` / `top` を必須とする。`back` がなければ背面推定が未確定事項として残る。組立前の全身画像は `assembly_concept` として由来参照・hash付きで固定する。
- `mwb comparison brief/create/review` で一次資料とBlender実モデルの全身・部品・部品拡大レンダーを同じ視点で比較する。初回はカメラを自動決定し、次の候補では比較IDを指定して条件を再利用できる。レビューは全身、保持条件、全対象部品、親計画の全要件を記録する。
- `mwb quality-issue add/list/next/evaluate` で全身レビューの課題を部品・接続・参照方向・候補IDへ結び、各候補で解消度を記録できる。再評価には当該候補の比較IDと比較レビューを要する。必須課題がすべて同一候補・最新比較で `resolved` でない場合、完成候補を指定できない。
- `mwb completion set/list` で制作終点となる全身候補を一件指定し、後続候補へ更新した場合は履歴に前候補を残す。これはv2の正式採用や出力を実行しない。
- `mwb candidate edit-start <candidate-id> --production <production-id>` はhash検証済みの作業用 `.blend` コピーとsession IDを返す。CodexはBlender MCPで `blender_session.connect` を実行し、`candidate edit-bind` で実際のシーンを照合する。編集後に `blender_session.capture` で同じコピーを保存し、`candidate edit-finish <session-id> --result <working.blend> --file <edit.json>` で既存Blender検査を通した派生候補を取り込む。全身の部品形状修正では、変更部品の独立候補も抽出し、再組立てに使える。

画像そのものの生成はハーネス外で行い、`reference-pack brief` が生成指示と元資料を返す。生成画像は由来・推定事項を付けて登録する。比較用レンダーはBlenderのヘッドレス実行で作成し、人が画像を見て評価する。対話中のMCP編集操作自体はCodexが指示に応じて実行する。実際のMCP接続については起動中サーバーでの検証が残る。対話試験のコマンドとJSON例は [操作手順 ver3.0](operation-manual-v3.0.md) に記す。
